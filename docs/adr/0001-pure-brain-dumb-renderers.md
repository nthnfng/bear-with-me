# Barry's rules live in one pure brain; pages are dumb renderers

All of Barry's behaviour (modes, Confrontations, Slack passes, the Arm fight, Fatness, the Chud meter) lives in one pure function: `reduce(state, event) → {state, effects}`. Alongside it, `viewFor(state, tabId, now)` describes exactly what a tab should show, and the content scripts and popup only draw that description and report what the user did. We chose this so that every rule can be tested with Vitest without a browser, so the Reach stays in sync across tabs (it's one timestamp in one place instead of a timer per page), and so the overlay, popup and brain can be built in parallel against fixtures. Don't add behaviour to the overlay or popup, even small conditionals. Add it to the brain and expose it through the tab's view.
